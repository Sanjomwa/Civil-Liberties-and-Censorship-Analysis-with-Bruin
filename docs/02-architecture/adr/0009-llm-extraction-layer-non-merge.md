# ADR-0009: LLM Extraction Layer — Standalone, Disclosed, Non-Merge by Design

Status: Accepted, implemented; code deleted from the live repo 2026-08-03, superseded by `llm_report_writer/` (ADR-0010) — see "Amendment (2026-08-03)" below. **Corrected 2026-09-03: this Status line previously read only "Accepted, implemented" and did not reflect the amendment, even though the amendment section itself and `decision-log.md`'s ADR index already did.**
Date: 2026-08-02

## Context

CLIO has never had an AI/LLM layer. This ADR covers OTF-04 from the OTF ICRP grant punchlist: a narrow prototype proving that an LLM can extract discrete, location-specific events from a real news article as structured JSON, and that a separate, deterministic, non-LLM checker can verify every claimed quote actually appears in the source article before it is trusted. It is a prototype of the **extraction-and-grounding mechanism**, nothing more — it does not claim to close any coverage gap (that requires a separate manual audit, out of scope here) and it does not make a predictive/leading-indicator claim (this project already found, in earlier work, that it cannot statistically support one given how few historical crisis windows Kenya has).

This repo's `docs/07-governance/` folder is gitignored (per this project's public-repository docs policy) and did not contain an `ai-output-governance.md` file at the start of this session. Rather than create a new gitignored file this ADR would then depend on silently existing, the three governing rules are restated here in full so this ADR is self-contained, the same pattern ADR-0008 already used for the Evidence Source Acceptance Framework's eleven dimensions:

1. **Methodology-conformance.** Every AI-generated factual claim must be traceable to a verifiable primary source, or explicitly disclosed as unverifiable. Nothing here should ever claim a fact the source article doesn't actually contain.
2. **Disclosure and non-merge.** AI-generated output is its own separate, clearly labeled item — every record carries `llm_derived: true` and lands in its own table/dataset, with mandatory verbatim-quote grounding checked programmatically against the source text (not just trusted from the model). This output must never be joined into `composite_pressure_score`, `fact_country_pressure_daily`, or the ACLED regime engine's output without a future ADR.
3. **Scope-discipline.** Stays inside CLIO's actual mission — Kenya pilot, evidence fusion, not prediction, not general-purpose, not multi-country.

Two design risks were identified and resolved before this became permanent, not after:

- **A real grounding-checker defect**, found and fixed during a Fable-5 advisory review of `grounding_check.py` before this repo ever saw it: the original tier-2 near-match threshold (0.995 SequenceMatcher similarity) would classify a long quote with a single digit silently altered — e.g. a casualty count changed from 5 to 45 — as `MATCHED`, since overall textual similarity stays extremely high even when the one number that matters is wrong. Fixed by requiring every digit token present in a claimed quote to also appear, unchanged, in the matched source window before tier 2 can return `MATCHED`; otherwise it is demoted to `FUZZY` regardless of overall similarity score. Locked in by `test_altered_digit_in_otherwise_real_quote_is_not_matched` in `llm_extraction/tests/test_grounding_check.py`.
- **Copyright risk from committing full news-article body text to a public repository.** The Star and Daily Nation articles used as this prototype's seed data are real, copyrighted third-party journalism, not CLIO's own work. Resolved via a split: `llm_extraction/source_articles_manifest.json` (tracked, public-safe — URL, title, outlet, publish date, and a SHA-256 of the body text) versus `llm_extraction/source_articles_cache/` (gitignored, holds the actual body text locally only). `fetch_articles.py` lets a future contributor without the cache reproduce it from the live URL, verifying the fetched text's hash against the manifest rather than silently trusting a page that may have changed since 2026-08-02.

The OpenAI `gpt-5.4-mini` model was the specified provider/model choice, made for cost reasons. Before `extract_openai.py` was written, the live API was probed directly (per this project's own "verify before acting" discipline) rather than assumed from memory or documentation: `gpt-5.4-mini` rejects the `max_tokens` parameter (`max_completion_tokens` is required instead — confirmed via a live `BadRequestError`), `response.model` returns the real resolved snapshot (`gpt-5.4-mini-2026-03-17` at the time of this session, not the bare alias), and `message.refusal` and `choice.finish_reason` both live where the SDK's own type surface suggests. All three were exercised live with a schema shaped like the real extraction schema (nested array under a top-level object, nullable fields typed `["string", "null"]`, `strict: true`, `additionalProperties: false` throughout) before being relied on.

## Decision

Built `llm_extraction/` as a new top-level directory, parallel to `Bruin/`, `streamlit/`, and `scripts/` — deliberately outside all three, and specifically outside Bruin's dependency graph entirely. This is not just a documentation-level intention; two mechanisms enforce it:

1. **`setup_bigquery.py` writes only to a new, dedicated `llm_derived` BigQuery dataset** (`llm_derived.article_extractions`, `us-central1` — confirmed live as this project's existing dataset location before use, not assumed), fully separate from `civil_liberties_prod`/`staging`, `features`, `int`, `intelligence`, `marts`, and `reporting`. This dataset and table are never created or loaded via `bruin run` — only by manually invoking `python llm_extraction/setup_bigquery.py` and `python llm_extraction/run_extraction.py`. The reason is cost and determinism, not just namespacing: LLM calls are nondeterministic and billed per invocation, and Bruin's rebuild/backfill execution model would silently re-invoke and re-bill `extract_openai.py` on every DAG rebuild if this were wired in as a declared asset.
2. **A CI guard enforces the non-merge rule as a tested constraint, not a one-time review.** `llm_extraction/ci_check_no_merge.py` greps every `Bruin/assets/**/*.sql` file (confirmed live as the real asset glob, 42 files at the time of this session) for the literal string `llm_derived` and fails the build if any asset references it. Wired into `.github/workflows/tests.yml` as a step after the existing `pytest -q` run. Declaring this output outside Bruin's DAG was judged necessary but not sufficient — this project's own TD-42 already found a case where declared Bruin lineage and actual asset behavior diverged, so DAG placement alone was not trusted as the enforcement mechanism.

Every record produced by the pipeline is disclosed and stamped: `llm_derived: true`, `extraction_model` (the real API-returned snapshot string, not the requested alias), `extraction_timestamp_utc`, `prompt_version_hash` (a 12-character SHA-256 prefix of the exact system prompt text, computed at import time, so two extraction runs can be compared for whether they used the same prompt), `grounding_status`/`grounding_similarity` (from `grounding_check.py`, tier: `MATCHED`/`FUZZY`/`NOT_FOUND`), `grounding_checker_version`, and `review_status` (`pending_human_review` for any `FUZZY` quote, `not_required` otherwise). `approx_participants` is also run through the same grounding checker when non-null, since the extraction prompt requires it to copy the article's own wording rather than compute or estimate a figure.

OpenAI's structured outputs (`response_format={"type": "json_schema", ...}` with `strict: true`) were used for schema guarantees on every extraction call — this guarantees shape, not truth; `grounding_check.py`'s programmatic verification against the actual source text remains the real control on whether a claim is trustworthy.

## Consequences

This is additive and isolated. No existing CLIO table, score, mart, or dashboard page changes as a result of this ADR — `composite_pressure_score`, `fact_country_pressure_daily`, and the ACLED regime engine's output are all untouched, and the non-merge CI guard now makes that a tested property rather than a claim. This ADR does not establish or imply any coverage-gap finding (a separate, not-yet-performed manual audit would be required to claim that) and does not establish or imply any predictive/leading-indicator claim.

Any future request to join `llm_derived.article_extractions` output into an existing CLIO composite, mart, or the ACLED regime engine requires a new ADR that explicitly supersedes this one — the CI guard in `.github/workflows/tests.yml` will fail any Bruin asset that attempts this without one.

Scaling this prototype beyond the two seed articles (broader source coverage, a real coverage-gap audit, additional event types, additional languages) is out of scope for this ADR and would warrant its own follow-up decision once the mechanism has had an observation period, consistent with how this project has previously deferred Path A/Path B's own retirement question (ADR-0002) pending real evidence rather than deciding it up front.

## Amendment (2026-08-03): `llm_extraction/` deleted from the live repo

Per Sam's explicit direction (2026-08-02), `llm_extraction/` was removed from this repository's working tree entirely on 2026-08-03 — not archived, not left as "documented negative-result infrastructure" as originally planned. This is a deliberate reversal of the disposition this ADR originally recorded (keep the code, non-merge-guarded, as a standing prototype); the reasoning and evidence captured above (the grounding-checker fix, the copyright-handling split, the two-mechanism non-merge enforcement, the live extraction results) remain the accurate historical record of what was built and why — only the runnable code is gone.

What was actually removed from the working tree:
- The `llm_extraction/` directory in full (all seven `.py` files, `README.md`, `requirements.txt`, `tests/`, `source_articles_manifest.json`, the gitignored `source_articles_cache/` and `output/` directories).
- The CI non-merge guard step in `.github/workflows/tests.yml` (`OTF-04 non-merge guard`, `python llm_extraction/ci_check_no_merge.py`) — deleting the script it invoked would otherwise have failed every subsequent CI run.
- The two `llm_extraction/`-scoped `.gitignore` entries (`source_articles_cache/`, `output/`) and their explanatory comment, now dangling since the directory they scoped no longer exists.

What was deliberately **not** touched: the live `encoded-joy-485413-k5.llm_derived.article_extractions` BigQuery dataset and its 60 rows. Dropping a live BigQuery dataset is a separate, more consequential decision than deleting working-tree code and was explicitly out of scope for the deletion pass — confirmed still present via `bq ls` on 2026-08-03.

`llm_report_writer/` (see ADR-0010, once landed in this repo) is the prototype taking this ADR's place as CLIO's flagship AI-layer story going forward — a narration-of-already-verified-data design rather than this ADR's raw-article-extraction design. This amendment does not retract this ADR's findings; it records that the code has been superseded and removed.
